# Developer documentation

Build useful tools with independent ReAI plugins. This site is public: browsing plugin introductions and documentation does not require an account.

## Start here

1. [Build your first plugin](/en/plugin-development-v1): identity, project structure, lifecycle, and capabilities.
2. [Read API contracts](/en/plugin-api-reference-v1): use supported versioned APIs and minimal permissions.
3. [Create a consistent interface](/en/plugin-design-system-v1): theme tokens, layout, accessibility, and actual states.
4. [Prepare review and release](/en/plugin-submission-v1): independent validation, package identity, and release notes.

## Delivery boundaries

A local build, source review, platform approval, public release, and real Host installation are separate milestones. Match the current Host API and submission contracts rather than assuming that a source candidate is already available in production.

English pages are concise reading guides to the existing specifications. The [complete Chinese documentation](/) retains exact API fields, examples, implementation status, and history. English interface text does not translate publisher-authored Catalog descriptions automatically.
